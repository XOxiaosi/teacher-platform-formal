## 2. 总目标与结束条件

教师应能在同一网页会话中持续交办教学工作：助手记得原目标，只补问真正缺少的信息，按事项说明完成程度，完成写入后在对应页面立即可核对。会话主区采用用户已明确的 Codex 式信息层级；视觉风格通过样板页审阅后再推广。

本轮网页阶段完成需要同时满足：

1. 文档真源、修改意见和动态日志职责清楚，历史材料清理后无断链。
2. 同一会话的补充、纠错和继续指令不丢失原目标。
3. 模型轮次结束不再冒充业务完成；多事项逐项显示真实状态。
4. 写入后相关页面可立即核对，失败与重试不会重复写入。
5. 排课与备忘具备与产品规则一致的准备、确认、执行和回执。
6. AI 工作台样板页可打开，用户能针对布局、信息密度和视觉方向作出实际判断。
7. 样板页获得用户认可后，才进入 UI-002 全页面推广；工程检查通过与用户视觉认可分别记录。

### CHAT-001｜同会话上下文与任务接续

目标：

- 同一会话的每条新消息都能访问必要的已保存历史、活动目标和未完成事项。
- 内部新建 task 不得让模型失去同会话上下文；恢复、重试和幂等仍按教师隔离。
- 补充信息属于原任务时，继续推进原任务，不另造互相矛盾的目标。

必须覆盖：

- 用户消息、助手最终答复、已确认结果和待补信息的选择规则。
- 历史截断、摘要或窗口限制下的可恢复目标，不将内部日志和隐私字段塞入模型上下文。
- 归档会话、切换教师、重启恢复和重放时不串会话、不串教师。

验收：

- 合成教师先交办“两名学生、两节课、一条待办”，下一轮只补年级；助手能引用原课次和待办。
- 下一轮说“课程也添加一下”，助手不要求重述学生和时间。
- 重试或刷新后仍保持目标；第二位教师无法看到第一位教师的上下文。

### CHAT-002｜真实状态、业务回执与写后刷新

目标：

- 分开 model turn、task execution 和 business item 三层状态。
- 一条请求中的每个交办事项都有独立状态和可核对结果。
- 助手工具写入成功后刷新工作区资料；刷新失败也不重复执行写入。

建议的教师可见状态：

| 状态 | 含义 |
|---|---|
| 正在处理 | 当前仍有执行或模型输出 |
| 等待补充 | 缺少完成该事项所需的具体信息 |
| 等待确认 | 具体变更与影响已经准备好，等待教师确认 |
| 已保存 | 有持久化业务回执，并能在对应页面核对 |
| 部分完成 | 同一请求只有部分事项有完成回执 |
| 未执行 | 尚未调用可改变资料的业务操作 |
| 失败 | 执行失败，说明已保存与未保存部分及下一步 |
| 当前无法执行 | 能力尚未接入；不得显示成功或已完成 |

低风险学生新增边界：

- 教师明确提出新增，且提供姓名、年级时，该指令视为本次新增授权。
- 对象或必填信息不明确时先澄清。
- 该规则不扩展到学生资料修改、合并、归属变更或删除。

验收：

- 新增两名合成学生后，学生列表无需手动刷新即可看见；结果卡可直接打开对应学生。
- 重复 client request、刷新、轮询和重试不会重复创建学生。
- 学生已保存、课程待确认、待办未执行时，整项显示“部分完成”，不显示“已完成”。
- 页面刷新失败时显示“已保存但未加载最新资料”，再次刷新只读数据，不重做写入。

### CHAT-003｜排课与备忘确认闭环

排课：

- 复用 F04 已有日期、时间、对象、地点、形式、重复和冲突规则。
- 缺少具体日期、重复方式或地点等必要信息时只追问该项。
- 确认前展示具体安排、冲突与影响；确认后写入并显示课表变化。
- 小班名单尚待补充时保留待补状态，不将不完整安排冒充正式课程。

备忘：

- 复用 F12 的新增、查看、修改、完成和关联对象规则。
- 对象和时间明确时准备具体备忘；需要正式写入时按统一确认规则执行。
- 写入后在今日工作台或待办入口可核对。

验收：

- 使用合成学生完成一次单次课程和一条联系家长待办；确认前不落正式资料，确认后分别出现在课表和待办。
- 取消确认不写入；重复确认不重复建课或建待办。
- 排课成功、备忘失败时逐项回执，重试只处理失败项。

### UI-001｜AI 工作台视觉样板

已确认的信息层级：

- 左侧为紧凑、可收起的会话列表；不恢复任务看板。
- 主区顶部只有短标题、轻量同步状态和操作菜单。
- 中间为连续消息流，处理过程归属对应轮次并默认折叠。
- 结果卡突出对象、业务状态和下一步；不显示内部 ID、event key 或开发术语。
- 底部为紧凑输入框，短句保持低高度，长内容适度增高并在上限后框内滚动。

样板页需要展示的合成状态：

- 普通问答、助手正在输出、处理过程折叠与展开。
- 多事项部分完成、等待补充、等待确认、保存失败。
- 新增学生成功并提供查看入口。
- 排课待确认和当前能力未接入两种不同表达。
- 长对话向上阅读、出现新消息和“回到底部”。

视觉候选：

- 可尝试暖白背景、陶土橙强调色、深色正文、轻边框和适度留白。
- 可评估 shadcn/ui 作为基础组件；安装或接入不构成验收通过。
- 不在样板前冻结具体颜色值、组件库、图标或 Tailwind 配置。

UI-001 验收：

1. 打开已有会话首屏即可阅读最近问答。
2. 任务过程默认不压住正文，展开后仍清楚。
3. 会话列表和输入区明显比当前卡片式页面紧凑。
4. 同类状态有一致文字、图标和操作，不只依赖颜色。
5. Enter 发送、Shift+Enter 换行、失败保留草稿。
6. 底部自动跟随；向上阅读不跳；离底才显示回到底部。
7. 自动化、真实浏览器交互和用户视觉审阅分别记录。

UI-001 的最终 Gate 是用户实际审阅。暖白、陶土橙或 shadcn/ui 任一候选未获认可时，允许修改样板，不反向改变 CHAT-001 至 CHAT-003 的产品正确性要求。

### UI-002｜主题沉淀与教师端推广

用户认可 UI-001 后：

1. 固化字体、颜色、间距、按钮、表单、弹窗、状态、空数据和加载规则。
2. 先推广学生档案，再推广课表与课程详情，随后推广家长反馈。
3. 每个页面保留原有业务、保存恢复、对象隔离和确认边界。
4. 管理后台是否同期调整继续受 D08 约束。
5. 375、390、430 像素正式验收继续有效；“手机开发后置”只表示实施顺序，不等于可宣布整体视觉完成。

每页单独完成真实任务验收后再进入下一页；不能以公共组件安装成功代替页面完成。

## 5. 风险与控制

| 风险 | 影响 | 控制 |
|---|---|---|
| 为修上下文而发送过多历史 | 成本、隐私和模型噪声增加 | 只传必要业务历史；保留教师隔离、截断和摘要验证 |
| completed 语义一次性替换 | 破坏恢复、重试或监控 | 保留内部执行状态，新增业务事项投影，不用一个字段承担三层含义 |
| 写后刷新再次触发写入 | 重复学生、课程或待办 | 写事务与只读 invalidation 分离；使用现有幂等键 |
| 样板页伪造能力已完成 | 用户误判当前可用范围 | 合成状态明确标注；正式完成只接受持久化回执 |
| Tailwind 或组件库覆盖旧样式 | 现有页面回归 | UI-001 隔离验证；认可后再建立公共主题并逐页替换 |
| 历史清理破坏引用 | 治理失败、证据不可找回 | 精确清单、源码树外备份、更新引用并跑完整治理检查 |

## 6. 仍需用户决定的 Gate

- UI-001 样板页的视觉方向、信息密度和区域比例是否认可。
- 样板认可后 UI-002 的完整推广顺序是否需要调整。
- 管理后台是否同期视觉改造，继续按 D08 处理。

这些决定不阻塞 CHAT-001、CHAT-002、CHAT-003 以及其他与视觉无关、依赖已满足的已授权后端工作。
